# 研发交付产物契约

- 版本：1.1.0（2026-10-14）
- 使用者：`dev`、`to-spec`、`verify-change`、`setup-verification` 与项目自有验证入口。
- 用途：交接需要时复用字段；小任务可在对话/PR 中使用适用子集，不强制生成完整文档。
- 存储：沿用项目 spec/任务/PR/工件位置，缺少约定时用仓库 Markdown。以下命令和数据均为格式示例，不代表任一业务项目已支持。

## 1. 实施规格

输入来源、确认状态及目标/非目标；必要业务规则、架构与测试缝；独立验收；任务及依赖。已有材料引用即可，难回退的真实取舍才记 ADR。

| 字段 | 含义 |
| --- | --- |
| 规则/AC ID | 需要跨任务追踪时编号；不强制为所有小改动编号 |
| 前置与入口 | 角色、状态、数据、真实操作和允许环境 |
| 独立预期 | 确认实例、正式契约、不变量、范围或明确评分判据；不能调用生产算法生成 expected |
| 副作用 | 实际持久化、关联状态/事件以及应当不发生的变化，按业务需要断言 |
| 验证 | 对应层级、公共测试缝、真实依赖与外部替身限制 |
| 持续回归 | 是否需要确定性检查和运行频率；已知关键场景可直接编写，不等待探索成功 |
| 确认状态 | 已确认来源、授权内代理决定、推断、待决策；不把推荐或运行结果写成人的确认 |

示例：

| AC | 来源与前置 | 操作 | 预期与副作用 | 验证 |
| --- | --- | --- | --- | --- |
| AC-01 | BR-01，A 管理员 | 创建名称为 sample 的记录 | 201，返回非空 ID，读取同一 ID 的名称/租户符合输入，插入一条业务记录 | 真实 API + SQLite 集成，持续回归 |
| AC-02 | BR-02，B 管理员、A 的记录 | 删除 A 的记录 | 403；原业务记录不变；拒绝审计符合规则 | 权限集成，必要用户入口验证 |

动态 ID 通过关联关系验证，不能预设某个值；订单金额等固定例子可给字面值。AI 产品另给样本集、质量判据和不确定性说明。

任务切片写明行为、覆盖场景、允许范围、真正的 blocker、验证入口和必要负责人。只更新受影响的功能地图。广泛机械迁移采用兼容扩展/批量迁移/收缩，或注明集成分支最终验证点。

## 2. 验证证据

交接必须能追溯到实际运行的对象。推荐字段：

```json
{
  "run_id": "run-20261014-01",
  "subject": {
    "commit": "actual-sha-or-null",
    "artifact_digest": "actual-digest-or-null",
    "working_tree": "clean-or-dirty",
    "patch_digest": "actual-diff-digest-if-dirty"
  },
  "environment": {"target": "local", "config_scope": "isolated-test-data"},
  "checks": [
    {"ac": "AC-02", "entry": "DELETE /items/id", "expected": "403; business row unchanged", "actual": "observed values", "status": "PASS", "artifacts": ["trace-or-report-path"]}
  ],
  "coverage_gaps": [],
  "cleanup": {"owned_resources_removed": true, "evidence_preserved": true}
}
```

字段值必须是实际观测或明确 null/未验证，不复制示例值。target 环境名不等于无副作用，秘密和敏感数据脱敏。截图、API 结果、持久化查询、日志/trace 根据场景选择，不能互相冒充。

结果区分 PASS、FAIL、NOT_RUN、BLOCKED 和 APPROVED_EXCEPTION；例外记录批准者/来源、原因与补偿。通过汇总不能隐藏关键失败、未运行或版本错配。

关键反向验证记录：隔离方式、错误版本或变异、目标断言实际失败原因、正确版本通过和资源清理。语法/fixture/环境错误不是有效反向证明。已知缺陷旧版本失败证据可复用，不要求全部测试变异；禁止改写用户工作目录制造红灯。

遇到失败可先记 UNKNOWN 原因，通过证据区分环境、夹具、测试和产品，不强迫猜一个分类。正确断言不为实现让步；修正真实测试错误时记录根据。偶发失败保留条件与频率，重试通过不抹去首轮失败。

## 3. 项目验证适配

项目自有 `verify-<app>` 通常保存于目标仓库 `.agents/skills/`，随代码提交。仓库规定路径优先；本 ai-skills 的 `.agents/skills` 仅存发布器链接，实体样例须在临时目标或 fixtures 中体现。

入口应说明：

| 信息 | 要求 |
| --- | --- |
| Launch/Doctor | 实际启动/就绪信号、超时、版本/制品、允许环境和失败取证 |
| Data | 隔离角色/租户与 run ID、seed/reset 的影响边界；不写真实秘密 |
| Drive/Observe | 用户入口、公共 API/CLI 或设备操作、独立断言、必要只读状态与关联日志 |
| Evidence | 位置、结果格式、覆盖范围、保留和脱敏 |
| Cleanup | 只停止本次进程/容器、删除本次数据；失败也清理，证据保留 |
| Targets | 实际支持的 local/ci/staging/prod-smoke，缺条件的目标明确未验证 |

可以合并短章节，不为符合目录结构填假命令。功能地图引用真实脚本和场景：行为/路径、必要前置、入口与证明、重要陷阱；只维护受影响内容。

生成器交付前实际执行代表性正常及适用拒绝/失败路径，确认清理后证据可读。缺环境的部分是草案/blocked。maintain 先检查受影响入口：clean 只针对声明范围；changed 更新运行协议后复跑；blocked 不放宽正确断言、不自动改产品。全量或定时巡检按需求/预算选择。

CLI 足够时不要求 MCP。生产只读诊断与测试数据写入分离；prod-smoke 不部署、回滚或写生产数据。共享 staging 不全量 reset。

## 4. 发布交接与完成状态

| 状态 | 至少需要 |
| --- | --- |
| 已实施 | 变更存在，不暗示所有测试已通过 |
| 已验证 | 相关验收在明确版本/环境有证据，缺口逐项报告 |
| 测试环境可发布 | 最终变更/实际合并结果的必要 CI 和审查通过、制品明确 |
| 测试环境已验证 | 部署制品匹配且必要 smoke 通过 |
| 待人工生产发布 | 发布包完成，生产尚未执行 |
| 生产已部署/已观察 | 人的部署记录和允许的只读验证结果分别记录 |

发布包包含 spec/变更摘要、版本及制品摘要、CI/测试环境部署与验收结果、覆盖缺口、真实迁移和兼容顺序、恢复方法、观察项及负责人。只放本次适用内容。

代码合并、生产部署/回滚/实际数据操作由人执行。测试环境由已有授权流水线自动部署。Agent 准备交接物、分析失败和报告只读 smoke，不以方案授权代替生产操作权限。

代码回退不保证恢复 schema/数据；按兼容窗口记录可行恢复及验证。变更、冲突解决、配置或基线变化时检查证据是否仍对应，不能沿用别的提交/制品绿灯。
