# 用实验回答设计问题

先固定一个问题、候选、不变量、观察方式和停止条件；原型回答实现/交互事实，不替用户批准业务规则。已有需求可直接实施时不另造原型。

- **逻辑/状态**：优先纯逻辑加可观察状态；需要非开发者操作时可做单个自包含 HTML，列出正常、边界及失败的操作路径。没有持久化问题时使用内存；确需数据库时只用明确隔离数据。
- **UI**：复用已有用户任务、品牌和约束，按可用设计能力探索有实质区别的候选。项目已有 `x-ui` 时按需选择；不为探索改动真实业务事实。

隔离目录/worktree 或项目已有试验位置中实现最短可运行版本，标记 prototype 与局限。原型不强制产品级抽象和完整测试，但必须实际运行能回答问题的代表操作；运行失败时只能交付未验证草案，源码检查不能冒充交互验证。

记录问题、版本/入口、输入/操作、实际结果、结论与仍未确定的事项。决定按已有授权进入 spec/ADR；原始可运行材料保存为可查指针，不只留口头总结。提交到试验分支、推送或写 tracker 均复用授权，不自动提交所有用户改动。

不把探索稿标成生产实现，不默认删除可追溯证据，也不默认将原型整套并入主干。用户只要求探索时到结论结束，不擅自实施正式功能。
