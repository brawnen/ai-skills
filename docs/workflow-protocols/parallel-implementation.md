# 整份规格的任务图实施

输入：明确 spec、带 source 和真实阻塞边的任务图、起始提交、集成目标与允许范围。使用 tickets 协议及入口提供的图校验脚本先查重复/未知依赖、环和状态；图快照每次调度前对照 tracker 与实际集成结果。

只有用户或适用指令明确授权委派且宿主可用时启动子代理。没有授权/能力时按图顺序实施，标明模式，不用另开 CLI agent 绕过限制。并发上限遵循已有预算；没有约定时保守选择可独立写入的任务，不追求最大并发。

1. 记录起始提交和集成分支，检查已有未提交工作与目录归属，不重置用户工作区。共享接口先收敛，必要的 prefactor 是真实 blocker。
2. 只领取 ready frontier 中未被占用的任务。一个任务一个所有者，独立 worktree/分支从集成基线出发；基线错误时安全重建或协商，不盲目 reset。
3. 给实施者 spec/任务/接口/验收/权限与必要原始证据指针，按 implementation 协议完成。TDD、审查或研究各按条件选择，不强制为每项增加角色。
4. 返回提交、基线、运行证据与剩余风险。协调者先验证来源再串行整合；若集成 tip 已变化，先在任务分支更新集成结果，解决冲突并复验，再 fast-forward 集成；项目要求其他合并策略时依项目。
5. 合并失败或冲突未决时保留分支和证据，任务不能标 done，下游不能提前启动。每次整合后重新计算 frontier。
6. 对最终集成版本执行必要验收、双轴审查和 CI。交给独立审查者的是整份规格及验收、项目规范、从集成起点到最终提交的完整 diff 和对应运行证据。协调者暂存各实施者的总结，按[独立审查的材料交接](review.md#独立审查的材料交接)在初判后提供。分任务结果不能代替集成结论；按项目门禁更新完成状态。
7. 按授权创建/更新 PR，使用 pr 协议；输出分支、任务/AC 状态、检查、缺口和交接。生产部署由人执行。
8. 清理仅限本次创建且成果已保留的 worktree/临时数据。中断或失败时保留可恢复提交与证据，报告剩余资源，不删除别人的目录。

提交、推送和合入受保护主干分别复用相应授权；实现整份规格不等于永久批准任意仓库操作。无需为同一已确认授权反复询问。
