# 编写与修剪供 Agent 使用的说明

参考 Matt Pocock `writing-for-agents`（含 `SKILL-MECHANICS.md`）与 `chief-of-staff` 历史锚定规则，适用于 `AGENTS.md`、`SKILL.md` 及通过条件指针读取的工程文档：

1. **逐句 No-op 剔除测试**：只保留真正改变当前前沿模型与宿主默认行为的约束、项目专有事实与工具协议。逐句审视“如果删掉这句，Agent 的默认行为会变差吗？”——不会变差的常识句整句删除（而非删减修饰词），防止长期“只增不减”沉淀出稀释注意力的文字泥沙（Sediment）。
2. **常驻成本与调用权衡**：`AGENTS.md` 与已安装 skill 的 `description` 每轮强制加载，有固定上下文成本。只有需要 Agent 自动发现或被其他 skill 路由的能力才配常驻 `description`；条件专属方法下沉为参考文件，指针必须写清**在什么具体条件下读取**，禁止模糊写“参见某文档”。独立入口须有高频独立使用价值，不为命名对称拆分薄壳 skill。
3. **单一事实源与就近存放**：每个事实只留一处权威来源；可从 `package.json`、配置或目录廉价查到的命令与清单不重复缓存，只保留配置看不出的取舍原因与陷阱。模块局部约定（如包导入边界）就近放在对应目录 `README.md`，根 `AGENTS.md` 仅留一行条件指针。
4. **正向默认路径优于禁令堆叠**：修改指令先找真实失败证据，优先按约束漏斗修结构、补类型/AST lint/测试（交 `x-guard`），其次改为清晰的正向默认动作与可检查的完成条件（Done when...），避免无限追加“禁止……”。
5. **历史结论锚定日期与 Commit**：在复盘记录、演进说明或项目知识页中描述代码状态时，必须绑定日期与精确版本（如 `截至 2026-11-27（repo@abc1234），某入口采用……`），不写裸“当前/目前”，确保代码演进后旧记录可被识别为被替代而非误导后续会话。
