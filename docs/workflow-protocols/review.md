# 代码双轴审查

固定审查范围：分支/提交比较需要实际可解析的基线与 HEAD；工作区审查必须包含已暂存、未暂存及与请求相关的新增文件。复用用户指定基线和仓库分支事实，不用 `HEAD...HEAD` 漏掉工作区，也不凭猜测比较无关分支。范围为空返回 no-op。

从改动路径和涉及的产品出发，主动查找仓库及模块的 `AGENTS.md`、`CONTRIBUTING.md`、`CODING_STANDARDS.md`、`DESIGN.md`、`GLOSSARY.md` 和项目自定义规范。沿 README、文档索引及其中的链接找到适用条款，即使规范在 diff 之外。核对目录范围、适用版本和例外，在发现中引用实际约束。规范冲突或找不到权威依据时说明限制。

对照上述规范、原始需求/spec 及必要调用方，分别形成两个轴的结论：

- **Standards**：项目规则、边界和结构判断。优先项目真实约定；工具已覆盖的格式问题交给工具。重点核查三类高发负债：
  1. **反逃生舱**：diff 中新增的 lint/type 抑制（`eslint-disable`、`@ts-ignore`、`nolint` 等）及掩盖自家代码坑的 `IMPORTANT / do not remove` 借口注释，若抑制的是正确性或安全规则则标为阻塞或必清缺陷；
  2. **反 AI 胶水膨胀（Deslop Shared Libs）**：检查本次改动是否重复造出了仓库公共层已有的近义 helper、DTO 转换器、请求/错误处理包装或防御性样板代码，提示合并复用而非任由工具函数蔓延；
  3. **结构负担与文档失步**：单调用方多层透传、未删死代码/废弃适配层即叠加新逻辑、以及改动已变更公共行为/环境变量/接口却未同步更新既有权威文档（如 `README`、`.env.example`、`DESIGN.md`、`GLOSSARY.md`），不把个人风格偏好称为违规。
- **Spec**：缺失、部分实现、错误语义和越界修改。即使测试 PASS，也检查断言是否足以支撑结论、未测分支/角色/数据/版本会否改变结果。涉及前端或客户端界面时，对照确认的 `x-ui` 视觉方向、`DESIGN.md` 与目标视口（Web `375px / 768px / 1440px` 响应式、手机拇指热区与安全区、后台表格对齐与单屏单主色）检查视觉还原度及加载、空、错误、权限状态是否完整，具备运行条件时结合内置浏览器实看验证，不以编译通过代替界面审视。不能通过补写与实现自洽的 spec 消除遗漏。

缺正式 spec 时可用用户任务中的独立预期；不足时说明限制，继续可进行的 Standards 审查。重大需求遗漏不能被规范通过抵消，两个轴各有结论；报告不强求凑出问题。

若任一轴的结论依赖某个一旦为假就会改变判断的事实，把它写成可证伪的具体预期。沿真实入口追到调用方、配置或消费者，优先核对与本次版本和环境匹配的原始运行证据。证据不足时，在隔离环境运行能区分两种结果的最小检查，观察目标行为。比如审查 CI 门禁，要核对指定用例实际执行，并验证用例跳过时门禁会失败。

在对应轴交代关键预期、依据和实际结果。证据证实或推翻了什么就写到什么范围；无法运行时注明尚未验证的前提及其影响。已有充分证据可直接复用，普通改动不强凑假设或重复跑全量。跨部署风险按需读取 `cross-boundary-design.md`，架构判断按需读取 `architecture-design.md`。

## 独立审查的材料交接

任务需要独立审查且委派已获授权时，选未参与实现的审查者，在新上下文中开始，不继承实现聊天。普通改动可由一个审查者分轴判断；大改动或高风险改动且授权并行时，可用两个各自独立的新上下文子代理并行分跑 Standards 与 Spec 再聚合，避免互相锚定。无法隔离时如实标记为自查或已接触实现说明的复核，并保留项目要求的独立门禁。

1. **先独判。** 协调者只交付原始需求及已确认决定、适用规范入口、准确的仓库与比较范围、原始运行工件及必要环境信息。待审代码、测试和文档完整可见。实现者的交接总结、预期结论及其他审查者的意见留到下一轮。审查者先返回带版本的 Standards / Spec 初判、发现与证据缺口；可沿用聊天记录，无需另写报告。
2. **再对照。** 初判已留存后，把实现者的说明交给同一审查者。对新增事实或与初判冲突的主张核对源码、原始证据，必要时定向实跑。说明哪些判断维持、哪些修正以及依据。没有实现说明时保留初判并注明。若实现已更新，按新版本复核受影响范围，不能把旧结论直接算作新版本通过。

每个发现说明具体文件/行或契约、可发生场景、影响、证据和最短修正方向；区分阻塞缺陷、重要建议、待验证假设。交付审查结果不自动修改代码、合并或部署；用户授权修复时再实施并验证。
