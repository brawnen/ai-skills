# PR 与发布交接说明

由宿主写 PR 时读取，不提供独立 pr skill。沿用仓库模板，复用实际 diff、需求和运行证据。短改动可以只有简短说明及验证，不强制新增章节或图示。

适用内容：

- **变化**：解决什么问题、实际改变什么行为。关系复杂时用最小必要的伪代码、调用/文件树、Mermaid 或 diff；图示服务判断，不填满所有形式。
- **证据**：对应版本/工作树/制品与环境，相关 AC 的实际运行结果及工件。修复可给前后证据，新行为可给正常/拒绝路径。没跑的写 NOT_RUN 或 BLOCKED，不编造前态结果或工件链接。
- **风险**：影响范围、是否可逆、兼容/迁移顺序、恢复方法、未验证项。代码回退不一定恢复数据；数据库真实操作风险另用 `x-db`。

视觉事实可用截图；权限、数据一致性和副作用需要行为断言。测试绿灯不批准新业务取舍，也不代表合并/部署授权。

PR 内容与后续生产发布包有联系但不混同：发布包另核对最终制品、CI、测试部署/smoke、观察与负责人。生产操作维持既有人工边界。

可视化选择借鉴 Dex Horthy / Humanlayer 的 show-me，经 Matt Pocock pr 方法引入；不依赖安装 show-me。来源及许可见同目录 UPSTREAM.md 与 LICENSE.mattpocock。
