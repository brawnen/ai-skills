# 变更验证与防自证判据

输入是已确认行为/AC、变更范围、目标版本和环境；没有正式 spec 时可用任务中的独立预期，不为测试补写整份文档。推断不足以确定业务正确时，只确认该缺口。

## 选择反馈与实景走查

确定受影响的规则、接口、依赖与用户旅程。复用已有静态、功能、契约/集成和真实入口测试；按影响及风险运行，不按工具清单遍历。纯 API/CLI 从其真实用户入口验证。

- **项目底座复用**：项目有 `verify-<app>` 时按其 doctor/操作协议执行相关路径；已有确定性测试覆盖真实入口且证据充分时，无需额外探索。没有专属 skill 但有可靠脚本时直接使用；缺运行环境则标出未覆盖部分。
- **前端与全栈界面三视口实景走查（借鉴 `gstack /qa`）**：当改动涉及 Web App、响应式 H5、跨端页面或后台管理系统且本地/预览环境可访问时，使用宿主内置隔离浏览器按真实用户身份走通受影响的核心旅程（关键点击、表单提交与校验、抽屉/弹窗开关、空/错误/无权限状态），同步检查：
  1. **运行态干净度**：浏览器 Console 无未捕获异常，Network 无非预期 4xx/5xx 或断流；
  2. **多视口几何可用性**：按产品形态核对 `375px`（手机竖屏）、`768px`（平板/窄分栏）、`1440px`（桌面宽屏）下无横向滚动溢出、文字截断乱码、主按钮被吸底栏/软键盘遮挡或明显偏离 `DESIGN.md`。
- **缺陷固化为回归**：已知关键场景直接写确定性回归进入 CI；实景走查或探索发现稳定缺陷时，保留复现输入并在合适层级（单元 / 接口契约 / 轻量浏览器断言）补齐回归测试，不把所有细枝末节都堆成昂贵 E2E。

## 独立判据与反向验证

期望来自需求、独立示例或正式契约，不导入生产结果作为 expected，也不复制同一算法。待验证行为从真实业务入口发生；夹具只能准备前置条件，不能直接写好待证明结果。

关键回归优先复用已知缺陷版本的失败证据。需要人为制造错误时，在隔离副本中按以下顺序验证：

1. 写明改变哪个行为、预计哪条断言会怎样失败。保存变异前的实际基线，包括与本次验证有关的未提交改动。
2. 变异后先对照基线查看实际 diff，确认目标代码或夹具确实改变、独立断言保持原样，且测试入口会使用这份副本或由它重建的制品。差异为空、改错位置或混入无关改动时，先纠正实验。
3. 运行目标用例，从输出核对用例名、失败断言和实际值。仅当失败与预测的业务错误吻合时，才采信红灯。跳过、环境错误或意外通过都要单独说明。恢复副本并核对与基线一致，在相同条件下复跑同一入口确认通过。

高后果、争议或证据不足时增加独立验证，委派须遵循宿主约束和已有授权。提供业务判据、目标版本、运行协议及允许范围，不让多个模型的同意代替实际证据。无法委派时如实说明独立性限制。

## 失败与报告

区分环境、夹具、测试缺陷、产品缺陷以及尚未确定的原因。依据证据修复；正确断言不为实现让步，确认测试/规格误解时可修正并解释。删测试、盲目重试和未经说明的 skip 不算解决问题。

偶发失败记录条件及失败率；无新代码、新疑点或新环境时不重复全量。疑难根因再使用 `x-debug`。环境、授权或判据阻塞时继续独立工作并报告具体缺口，不强迫归因或宣称通过。

需要交接时读取 [交付产物契约](artifacts.md#2-验证证据) 验证证据章节。记录 run ID、版本/制品和工作树变更标识、环境、场景、独立预期、实际结果、状态及工件。区分未运行、失败、环境阻塞和已确认例外。截图/编译/退出码不能单独证明业务副作用正确；清理只处理本次资源，保留脱敏证据。
