# CI 门禁、测试部署与生产发布交接

用于从代码审查/合入推进到测试环境验收与人工生产发布准备，也可单独执行发布就绪核查与发布包生成。生产部署、回滚与生产数据写入始终由人执行；agent 负责门禁核验、文档防腐败同步、授权范围内的测试环境部署/smoke、发布单编制及允许的只读观察。

## 1. 合并与 CI 门禁核对

1. **版本与比较范围锁定**：明确目标分支、待发布提交 SHA 及工作树状态；禁止拿旧提交或局部 worktree 的绿灯充当最终合并版本证据。
2. **门禁真实执行核验**：检查 CI 对应提交的关键作业（lint、typecheck、单元/集成测试、构建）是否实际运行并选中目标用例；关键用例被跳过（skip / 0 selected）不得视为门禁通过。
3. **制品标识确认**：记录本次构建产出的实际制品标识（镜像 digest、包版本、构建产物哈希或 commit 标签），后续部署与发布单统一绑定同一标识。
4. **授权合入**：在用户已授权目标分支、且满足分支保护与审查门禁时执行合并；未授权远端推送或合入受保护主干时，停在可合入状态并明确待人工动作。

## 2. 发布前就绪核查与文档同步（Release Checklist）

进入部署或生成发布包前，逐项核查本次变更的文档一致性与外部耦合：

- **权威文档防腐败同步（借鉴 `gstack /document-release`）**：对照本次分支实际 diff，检查项目中**已经存在**的 `README.md`、`AGENTS.md` / `CLAUDE.md`、`DESIGN.md`、`GLOSSARY.md` / `CONTEXT.md`、`.env.example` 及 OpenAPI/接口契约文档是否因本次改动失真；有漂移时原位更新对应条目（无对应文件时绝不硬造空模板），防止过期文档误导后续迭代的开发者与 Agent。
- **配置、密钥与人工外部向导**：列出新增、修改或废弃的环境变量、配置文件项、Secret/证书与 Feature Flag 默认值，禁止把代码默认值兜底当作生产配置已配好。若涉及必须由人在第三方网页控制台手工获取的密钥或开通动作（如支付、OAuth、云存储及同步写入 `.env` 与 GitHub Actions `secrets.*`），可衔接 `$x-dev` 的交互式向导协议（`<x-dev>/references/wizard-setup.md` 与 `<x-dev>/scripts/wizard-template.sh`）生成一次性配置向导辅助完成。
- **数据库与数据迁移顺序**：存在 DDL、索引、回填或数据修复时，联动 `x-db` 明确严格执行顺序：
  - *向后兼容扩展（Expand）*：先执行无损/在线迁移，再发布新代码；
  - *读写切换与回填*：确认新旧服务实例在滚动窗口内共存无错，分批幂等回填；
  - *破坏性收缩（Contract）*：仅在旧代码实例全部下线且观察稳定后单独执行，不与业务代码首轮上线混发。
- **跨服务与客户端兼容**：存在多服务调用、异步队列消息或未刷新前端/移动端旧版本时，核对发布先后顺序与降级兼容表现。

## 3. 测试环境（Staging）部署与 Smoke

在已有流水线或工具授权时自动推进测试环境验证；无环境或无权限时如实标为 `BLOCKED / NOT_RUN`，不得将 `implemented` 写成 `staging-verified`：

1. **触发与版本对齐**：通过项目既有部署入口发布第 1 节锁定的制品；部署后通过健康接口、版本端点或启动日志核实运行实例确为本次版本。
2. **核心链路与拒绝路径 Smoke**：优先复用项目 `verify-<app>` 或确定性脚本，验证本次受影响的核心正常业务路径、关键权限/业务拒绝路径及持久化副作用（前端变更同步在内置隔离浏览器核对核心页面无白屏/Console 致命错与资源加载 404）；失败时保留脱敏日志与请求标识，回到实施修复。
3. **测试资源清理**：仅清理本次 smoke 创建的隔离测试数据，不重置共享测试环境全表。

## 4. 人工生产发布包（可执行 Runbook）

所有生产变更交接时，按本次实际涉及的范围输出精炼、可直接由人工照单执行的生产发布包（不涉及的模块直接省略，不填大量“无”）：

- **发布摘要与制品**：变更目标、风险等级（可逆双向门 / 难逆单向门）、精确 commit SHA 与制品/镜像标识。
- **前置检查（Pre-flight）**：人工上线前必须确认的环境变量、密钥、外部开关、备份状态与依赖服务版本。
- **分步执行顺序（Execution Steps）**：按严格时间顺序列出迁移脚本、发布动作、配置切换与灰度的具体命令或平台操作入口。
- **上线后只读验证与观察（Post-deploy Watch）**：上线后 5~30 分钟内需核对的健康检查、关键业务指标、错误码/日志过滤条件及告警项；在允许只读访问时，agent 可协助查询并汇报观察结果。
- **停止阈值与回滚路径（Stop & Rollback）**：明确触发立即中止或回滚的可观察信号（如 5xx/特定业务错误激增、锁等待超时、队列堆积），以及精确回滚步骤——区分“仅回退应用版本即可恢复”与“已发生 schema/数据写入、需向前修复或按备份恢复”的真实边界。
