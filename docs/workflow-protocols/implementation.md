# 单任务实施

由宿主执行，不提供独立 implement skill。复用任务/小规格、起始版本、允许范围、业务预期和项目验证入口；缺关键判据才暂停相应部分。小而明确的任务直接实施，不补写空 spec/tickets。

领取带引用的任务时沿用[任务归属与标题核对](tickets.md#核对任务归属与标题)；同一次交付已核实的任务直接复用，换任务、仓库或来源发生变化时重新核对。

围绕完整可观察行为取得快速反馈。适合独立断言的新行为优先考虑 TDD；用户已选择 test-first 时使用 `x-tdd`。已有充分回归的重构、文档、机械改动或环境受限时选择适用策略，不伪造 RED 历史。涉及 Web、手机 App 或后台界面编码时，严格遵循已拍板的 `x-ui` 视觉样稿、项目 `DESIGN.md` tokens 与反 AI 塑料感审美底线（真实中文业务文案、完整空/错/加载状态、无渐变字与套娃卡片），并在真实目标视口（桌面/移动）打开验证实际排版与交互后再进入交付。

实施后按影响运行验证，必要时读取 verification 协议和项目 verify-app；审查依据 review 协议，既有充分证据不重复运行。问题修复后检查证据是否仍对应最终工作树、配置与环境。

分开记录 implemented、verified、integrated、staging-verified：写完代码不是业务验收完成，子任务通过也不是整份规格通过。失败如实分类并保留工件，继续不依赖阻塞的工作。

提交、推送、建 PR 和合并遵循已有授权与项目门禁。允许合并不等于允许任意目标分支或生产操作；已有授权不因阶段切换再次询问。PR 使用 pr 协议，测试部署与生产发布准备使用 release 协议及交付产物契约。
