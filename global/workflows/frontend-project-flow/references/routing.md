# Routing

在前端任务里，先判断这是不是“工程交付问题”还是“视觉风格问题”。

## 默认路径

大多数任务直接走工程交付路径：

- `requirements-clarification`：明确页面范围、关键状态、验收标准
- `task-todolist-execution`：多文件前端任务拆 TODO
- `safe-editing`：控制改动范围
- `test-first-development`：行为变更或 bugfix 需要先补测试时使用
- `task-report`：最后统一汇报

## 什么时候需要额外视觉 skill

只有在以下场景才值得叠加 taste-oriented skill：

- Landing page
- 品牌官网
- Portfolio
- Redesign，且用户明确追求视觉升级
- 用户明确说“不要模板感”“需要更强设计感”

如果任务是下面这些，默认不要叠加视觉 skill：

- Admin / dashboard / internal tools
- 数据表格 / 表单页
- 设置页 / CRUD 页
- 现有设计系统内的小范围页面补改

## 决策句式

先给一句判断：

- “这更像工程交付任务，先按现有设计系统落地，再做必要视觉校验。”
- “这更像品牌表达任务，工程落地之外还需要额外的 taste pass。”
