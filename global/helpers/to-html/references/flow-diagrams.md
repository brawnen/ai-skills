# Formal HTML Flow Diagrams

只在正文存在明确流程关系时读取本文件。先还原关系，再设计视觉；不能为了图形化发明源稿中
不存在的顺序、因果、分支或回路。

## 何时转换

以下内容在正式 HTML 中优先转换为流程图：

- 三个及以上有序阶段、操作步骤或成熟度路径；
- 存在条件分支、审批门槛、失败回路或重试路径；
- 存在跨角色、系统或团队的责任交接；
- 源稿使用多行 `→`、缩进箭头或连续段落表达前后依赖。

普通清单、并列事实、证据目录、优缺点和两个短项之间的简单关系继续使用列表或正文。
时间线只有在需要表达时间顺序时使用时间线样式，不要伪装成执行流程。

## 建模要求

1. 先列出节点、连接、方向、分支条件和回路终点，并与源稿逐项核对。
2. 每个节点使用短标题和一条必要说明；长解释放在图后正文，避免把段落塞进节点。
3. 决策门、验证门槛和责任主体使用文字标签，不能只靠形状或颜色暗示。
4. 保留 `已确认`、`推断`、`未验证`、`待确认` 等事实层级；流程图不能升级证据状态。

## HTML 表达

使用自包含、语义化 HTML/CSS，不依赖 Mermaid、远程脚本、Canvas 或构建链。线性流程至少
使用 `figure + figcaption + ol`，让关闭 CSS 后仍能按正确顺序阅读：

```html
<figure class="flow-figure" aria-labelledby="route-caption">
  <figcaption id="route-caption">推荐路线</figcaption>
  <ol class="process-flow">
    <li class="process-step">
      <strong>聚合成熟供给</strong>
      <span>先跑通真实交易。</span>
    </li>
    <li class="process-step">
      <strong>验证补贴闭环</strong>
      <span>用一个城市验证。</span>
    </li>
    <li class="process-step">
      <strong>选择性自部署</strong>
      <span>按实际负载决策。</span>
    </li>
  </ol>
</figure>
```

- 桌面端使用横向或分组网格，通过伪元素或纯 CSS 连接线显示方向。
- 窄屏改为纵向节点与向下连接，禁止依赖横向滚动才能理解完整流程。
- 分支流程显式标注条件和出口；复杂分支可使用嵌套有序列表或 CSS Grid，但 DOM 顺序必须合理。
- 连接线和箭头只作装饰；流程含义必须由节点顺序及文字标签共同表达。
- 使用 `break-inside: avoid` 保护节点；打印分页无法容纳整张图时，允许在阶段组之间断页，不能从节点中间截断。
- 图后保留必要的解释、风险和停止条件，不要让视觉图替代关键论证。

## 验证

- 对照源稿检查节点、顺序、分支和回路，没有新增或遗漏关系。
- 在桌面、窄屏和打印中确认箭头方向明确、文字不重叠、节点不被裁切。
- 临时关闭 CSS，确认语义顺序仍可理解；检查颜色不是唯一信息载体。
