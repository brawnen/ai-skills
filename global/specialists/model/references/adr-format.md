# ADR 格式

只有决定同时满足以下条件时才创建 ADR：

1. 改变决定的成本较高或难以回退。
2. 没有上下文时，未来维护者会认为当前选择令人意外。
3. 存在真实替代方案和明确取舍。

## 推荐结构

```markdown
# ADR-NNNN: <决定标题>

- 状态：Proposed / Accepted / Superseded
- 日期：YYYY-MM-DD
- 作用域：系统 / <bounded context>

## 背景
描述促成决定的约束和已确认事实。

## 决定
明确写出选择了什么。

## 备选方案
- 方案 A：收益、代价、为何未选
- 方案 B：收益、代价、为何未选

## 后果
- 正向影响：
- 负向影响：
- 运维、兼容和测试影响：

## 重新评估条件
出现哪些事实变化时应重新讨论。
```

不要用 ADR 记录普通实现细节、无争议约定、临时任务状态或可轻易修改的选择。替代旧 ADR 时新增 ADR 并标记 superseded，不静默改写历史决定。
