# 证据与市场调研方法

## 一、两轴证据模型

不要把“来源看起来权威”和“结论已经在本项目验证”混为一谈。

### 证据状态

| 状态 | 含义 | 可用于什么 |
| --- | --- | --- |
| 已验证 | 本轮直接核对文件、数据、现场、实验、合同或实物 | 陈述当前项目事实 |
| 用户确认 | 用户明确给出的业务、合作或决策前提 | 作为条件性分析输入 |
| 推断 | 多项证据支持的解释、预测或方案判断 | 形成假设和验证设计 |
| 未验证 | 缺少必要资料或独立验证 | 暴露缺口，不进入承诺 |
| 待决策 | 不是事实问题，必须由责任人选择 | 进入决策清单 |

### 来源等级

| 等级 | 典型来源 | 使用规则 |
| --- | --- | --- |
| R1 原始/一手 | 内部原始数据、现场观察、实验结果、合同；厂商官网、监管文件、论文原文 | 直接支持其明确覆盖的主张 |
| R2 可靠二手 | 权威行业报告、财经报道、合作方新闻稿、专业数据库 | 交叉验证、补足背景和规模口径 |
| R3 线索 | 聚合页、转载、论坛、招聘、销售材料、搜索摘要 | 用于发现待核实问题，不单独支撑关键结论 |
| R4 分析产物 | 研究者计算、分类、情景和推断 | 必须列假设与推导，不伪装成外部事实 |

同一来源可支持某个事实，却不能支持更大的结论。例如，官网写“支持 95% 设备”只证明厂商有该口径；设备清单、工作流层级、失败条件和客户实用性仍需实测。

## 二、事实优先级与冲突

项目内部同一主题冲突时，默认优先级为：

1. 用户当前明确决定；
2. 已签署合同、已接受 ADR 或正式决策记录；
3. 最新正式事实源文档和原始数据；
4. 其他分析、设计和会议纪要；
5. 会话交接、旧报告和未复核摘要。

不要默默拼接冲突结论。记录冲突来源、时间、差异和需要谁确认。派生报告不应反向覆盖原始证据。

## 三、主张账本

对影响投资、范围、架构或定价的主张建立最小账本：

| 字段 | 内容 |
| --- | --- |
| `claim` | 可判断真假的单一主张 |
| `decision_impact` | 它会改变什么决定 |
| `status` | 已验证 / 用户确认 / 推断 / 未验证 / 待决策 |
| `source_tier` | R1～R4 |
| `source` | 文件、页码、URL、访谈、实验或数据版本 |
| `as_of` | 来源日期或核对日期 |
| `scope` | 地区、客户、产品版本、样本和适用条件 |
| `supports` | 来源实际能证明什么 |
| `does_not_support` | 最容易被错误外推的部分 |
| `next_evidence` | 升级结论所需的下一项证据 |

账本可以是表格或结构化数据；只有关键主张需要逐条维护，不要把所有背景事实都变成繁重台账。

## 四、从资料盘点到任务链证据

盘点内部资料时，不只列文件名。按业务对象或案例把原始输入、中间结果、反馈、修订和最终结果串成一条链，检查：

- 是否是独立案例，还是同一案例的多个版本；
- 输入、目标真值和最终结果是否可配对；
- 文件名、版本、单位、对象和时间是否一致；
- 哪些字段来自客户，哪些来自人工推断或系统计算；
- 是否存在选择偏差、同源泄漏和只保留成功样本；
- 资料授权是否覆盖推理、训练、共享和发布。

优先选择少量“穿透样本”完整走通输入、修订和结果，再扩大横向样本。样本少时用留一分析观察失败类型，不把同一对象的多版本随机拆成训练与测试。

## 五、外部市场与竞品研究

### 先定义研究问题

每轮检索应服务于一个决定，例如：

- 目标工作流是否已经有预算和成熟替代品？
- 竞品覆盖的是设计、决策、执行还是最终质量责任？
- 客户按账号、席位、用量、项目、结果还是分成付费？
- 关键集成是开放、合作、封闭还是依赖人工？
- 哪个公开口径一旦被实测证实，会推翻当前差异化？

### 四类竞争对象

不要只列“长得像”的产品。至少检查：

1. **直接竞品**：同一用户、同一工作流、同一预算。
2. **上下游平台**：可能向本环节延伸或控制入口、数据、接口和渠道。
3. **替代方案**：人工、Excel、外包、旧软件、内部团队和“不做”。
4. **合作与使能方**：设备商、数据商、编译/支付/交付平台、渠道或监管许可方。

### 能力矩阵

用客户任务而不是营销功能名做行。每项至少记录：

- 输入起点和输出终点；
- 自动化深度与人工责任；
- 是否覆盖异常、约束和最终质量；
- 可验证证据和公开口径的限定词；
- 定价单位、目标用户、渠道和锁定方式；
- 对本项目是验证、威胁、替代、合作还是监控信号。

“AI”“端到端”“一键”“兼容”“自动”必须继续追问到输入、输出、范围、版本、失败和人工步骤。

### 市场规模

- Top-down 报告用于方向和数量级，不直接等于可获得收入。
- Bottom-up 至少需要目标账户数、符合条件比例、年合同额、采用率、销售周期和交付容量。
- 服务市场要扣除地域、行业细分、集成前提、预算和团队交付上限。
- 付费意愿优先用已付费替代品、试点报价、LOI、采购流程和实际合同验证；“感兴趣”只算线索。

## 六、研究输出

每个专题先写三栏：

| 能证明什么 | 不能证明什么 | 下一项证据 |
| --- | --- | --- |
| 直接受当前证据支持的结论 | 容易被误读或仍缺范围的结论 | 实验、访谈、合同、数据或实测 |

结论发生变化时，保留变化原因和新证据，不把历史估计继续当现状。对时间敏感的市场、价格和公司信息标注 `as of` 日期。
