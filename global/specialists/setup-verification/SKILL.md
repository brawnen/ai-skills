# 项目验证能力

create/maintain 共用一个入口。模式从任务和项目事实确定，不再增加选择问答；复用现有脚本、测试框架、容器与日志入口。

## 仓库取证

确认用户实际入口、启动/就绪、版本和配置、隔离数据与角色、操作工具、独立业务断言、观察和清理方法。仓库能回答的事实自行查询；必要账号、授权或业务预期缺失才询问。基线不可运行时报告原因，不能编造可运行指令，也不自动扩大到无关产品修复。

稳定操作先用项目脚本/CLI；MCP 仅用于确有缺口的共享远程数据或受控动作，不是默认前置条件。账号、秘密使用项目安全配置，不写进 skill 或证据。

## Create

需要协议或示例时读取 [项目适配契约](references/artifacts.md#3-项目验证适配)。在目标项目可提交的合法 skill 位置生成 `verify-<app>`，通常为 `.agents/skills/verify-<app>`；本仓库自身只能存发布器链接，不能在其忽略目录写实体样例。项目已有规则优先，禁止覆盖第三方或受管链接。

说明启动/Doctor、隔离 Data、真实 Drive、Observe、Evidence、Cleanup 与支持的 Targets。只写项目实际支持的能力，缺环境的 target 标为未验证；不为了完整填固定命令或数量。功能地图覆盖必要代表路径，版本化引用项目脚本而非复制实现。

交付前按说明实跑代表性正常及适用失败/拒绝路径：准备/Doctor、从入口执行业务、断言独立预期、保存证据、清理、核对证据保留。失败也清理本次资源；只管理自己创建的进程和数据，不按进程名或全表 reset 清理共享环境。未实际跑通的部分只能交付为草案/blocked。

## Maintain

先对照受影响代码/配置/入口与功能地图，再运行相关真实路径；有风险或漂移证据时扩大范围。定期或全量巡检需要明确需求和预算，不自动创建定时任务。

- clean：所声明范围验证通过；部分覆盖不称全项目 clean。
- changed：运行协议或地图需调整，修订后复跑；说明变更与证据。
- blocked：产品、环境、权限或业务判据阻塞，报告缺口；不放宽正确断言掩盖回归，不自动改产品代码。

代码合并、生产部署、回滚及写入由人执行。prod-smoke 仅采用允许的只读路径，检查真实版本并报告覆盖限制。更新共享环境时复用权限，不因目标名叫 staging 或 dry-run 就假定无副作用。
