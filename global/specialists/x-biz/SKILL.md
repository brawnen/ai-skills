# 商业模式与立项可行性评估

## 目标与裁剪原则

把分析变成可执行的商业或立项决定，而不是堆砌行业套话。最终必须回答：商业逻辑靠什么成立、最脆弱的假设是哪条、现在能批准什么、下一步用什么最小证据解锁后续投入。

按请求轻重自动裁剪深度，**绝不为轻量商业讨论硬套十章立项大报告**：

- **轻量商业模式 / 单位经济快算**（如“盘一下这个产品的商业模式”“算算这套 AI 工具怎么定价能回本”）：无需加载全部长参考，直接聚焦：**① 买方、使用者与现状替代方案 → ② 首个可收费切口与计费价值单位 → ③ 收入结构 vs 边际交付成本（含推理 Token/算力、人工服务、获客与渠道分成）→ ④ 盈亏平衡关键变量与最可能证伪它的 1~2 个实验**。
- **市场与竞品深挖**：验证真实预算、四类竞争对象（直接竞品、上下游延伸、人工/旧工具替代、合作使能方）与进入条件，读取 [证据与市场调研方法](references/evidence-and-market-research.md)。
- **综合可行性与阶段投资评审**：贯通机会、市场、商业模式、技术能力链与 Go/Adjust/Stop 阶段门，同时读取 [证据与市场调研方法](references/evidence-and-market-research.md) 与 [决策模型与交付模式](references/decision-models-and-deliverables.md)。

意图明确时直接进入对应模式；只有评估对象、目标读者或关键约束无法从上下文判断且会实质改变结论时才追问。

## 开始前

1. 明确当前要做的决定、时间窗口与可承受投入上限；读取可访问的文档、数据样本、现有流程和既有报告，能查证的事实不反问。
2. 永远把**现状替代方案**（人工、Excel、外包、旧软件和“不做”）作为比较基线——新方案必须相对现状创造可衡量的净价值。
3. 保密与数据边界：未经授权不把私有客户资料、内部成本或未公开设计发往外部服务。联网查证市场、竞品、价格与政策时优先一手来源并标注日期与口径范围。

## 核心纪律

### 1. 证据分层（严格区分事实与愿望）

统一区分五种状态，不把官方宣传稿或合作意向当成已落地事实：

- **已验证**：本轮从文件、数据、现场、代码、实验、合同或实物直接核对。
- **用户确认**：用户给出的业务或合作前提；作为条件性推演输入，不等同于外部市场已验证。
- **推断**：有证据支撑但仍需访谈、实验或真实交易验证的判断。
- **未验证**：当前材料无法回答的关键空白。
- **待决策**：必须由业务、产品或投资负责人拍板的选择。

### 2. 拆解任务链与最弱环（尤其针对 AI 产品）

不把“AI 能否做”当成单一黑盒：拆分为输入获取、理解/结构化、确定性规则/计算、生成/执行、结果验收与失败兜底。串联链路的总可行性受最弱环节约束；护城河必须落在专有配对数据、工作流嵌入、合法集成、质量闭环或渠道，而非泛称“接入大模型”。

### 3. 数字、成本与敏感性

- 准确率、周期、TAM、客单价、毛利和 ROI 必须注明实测值、外部口径或假设区间；缺少输入事实时保留计算公式与待取数项，**严禁编造虚假精确的五年财务预测表**。
- 区分现金支出、人力/机会成本与非现金合作意向；AI 产品的边际成本必须计入峰值/重试 Token 消耗、外部 API 调用、人工审核兜底与实施运维成本。
- 给基准 / 上行 / 下行情景的关键驱动变量，以及停止投入后仍可复用的剩余资产。

### 4. 最小验证闭环与阶段门

优先释放“购买证据”的小投入（穿透样本实测、付费试点、LOI），再释放“建设平台”的大投入。每个阶段明确：要消除的最大不确定性、可观察交付物与通过线、Go / Adjust / Stop 条件。

## 边界与协作

- 只要求分析或报告时，不自动启动代码开发、外部采购或试点操作。
- 想法尚处于早期发散、需要分轮访谈帮用户理清诉求或做问答式压力测试时，使用 `x-req`。
- 用户明确要求生成自包含、可打印的正式 HTML 决策简报时，配合 `x-html`（`decision-brief` 模板）交付；默认使用精炼 Markdown。
- 涉及具体跨端/跨服务/数据库架构边界风险时，按需读取 [跨边界设计参考](references/cross-boundary-design.md)。
