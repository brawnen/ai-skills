# 验证变更

输入是已确认行为/AC、变更范围、目标版本和环境；没有正式 spec 时可用任务中的独立预期，不为测试补写整份文档。推断不足以确定业务正确时，只确认该缺口。

## 选择反馈

确定受影响的规则、接口、依赖与旅程。复用已有静态、功能、契约/集成和真实入口测试；按影响及风险运行，不按工具清单遍历。纯 API/CLI 从其真实用户入口验证。

项目有 `verify-<app>` 时按其 doctor/操作协议执行相关路径；已有确定性测试覆盖真实入口且证据充分时，无需额外模型探索。没有专属 skill 但有可靠脚本时直接使用；缺运行环境则标出未覆盖部分。

关键已知场景可直接写确定性回归进入 CI，不等待探索成功。探索发现稳定缺陷或重要遗漏时，保留复现输入并固化适当层级的回归，不将每个场景都变成昂贵 E2E。

## 独立判据与反向验证

期望来自需求、独立示例或正式契约，不导入生产结果作为 expected，也不复制同一算法。待验证行为从真实业务入口发生；夹具只能准备前置条件，不能直接写好待证明结果。

关键新增/修复测试需要证明能检出目标错误：复跑已知缺陷版本，或在隔离 worktree/临时副本做针对性变异。绝不撤销用户工作目录中的修复或未提交变更。只有因目标业务错误失败才算反向证明；记录错误版本、失败原因、正确版本通过及隔离资源清理。既有有效回归证据可复用，不要求每次重做或全量变异。

高后果、争议或证据不足时增加独立验证，委派须遵循宿主约束和已有授权。提供业务判据、目标版本、运行协议及允许范围，不让多个模型的同意代替实际证据。无法委派时如实说明独立性限制。

## 失败与报告

区分环境、夹具、测试缺陷、产品缺陷以及尚未确定的原因。依据证据修复；正确断言不为实现让步，确认测试/规格误解时可修正并解释。删测试、盲目重试和未经说明的 skip 不算解决问题。

偶发失败记录条件及失败率；无新代码、新疑点或新环境时不重复全量。疑难根因再使用 `debug`。环境、授权或判据阻塞时继续独立工作并报告具体缺口，不强迫归因或宣称通过。

需要交接时读取 [证据契约](references/artifacts.md#2-验证证据)。记录 run ID、版本/制品和工作树变更标识、环境、场景、独立预期、实际结果、状态及工件。区分未运行、失败、环境阻塞和已确认例外。截图/编译/退出码不能单独证明业务副作用正确；清理只处理本次资源，保留脱敏证据。
