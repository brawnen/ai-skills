# 产品界面设计

面向 **Web App**、**手机 App** 与 **后台管理系统** 的全局高审美 UI/UX 设计主控入口。核心使命是：听懂非专业术语的直白描述，通过“看样选感觉”不断引导出用户真正想要的界面，拒绝 AI 廉价塑料感，并在定调后固化统一的设计体系。

## 场景分流（按任务成熟度自动选路）

- **0→1 新产品 / 新核心模块 / 整体改版（视觉方向未定）**：完整执行下方 **「四步渐进引导流」**（先对焦与看样定调，未确认方向前绝不盲写大批业务代码）。
- **已有成型设计系统 / 既有风格内新增常规页面**：直接读取并继承项目现有 `DESIGN.md`、样式 Tokens 与导航壳子，不为单个子页面重搞一套新风格；仅当本页布局存在明显取舍时给 2 个轻量结构方案确认后落地。
- **既有界面不好看 / 体验打磨 / 走查评分**：读取 [review-rubric.md](references/review-rubric.md) 或按 [capability-routing.md](references/capability-routing.md) 调用 `impeccable` 的 `critique` / `polish` / `bolder` / `quieter` / `harden`。
- **单处明确的样式小修（如改个间距或对齐）**：直接交回宿主修改并验证，不走完整流程。

## 0→1 与改版：四步渐进引导流

### 第 1 步：大白话对焦（禁专业术语）

读取 [discovery-and-prototyping.md](references/discovery-and-prototyping.md)。先读取已有需求或 `x-req` 产物，能查证的业务事实绝不重复提问。

1. 自动判定目标形态：**C端/品牌 Web App**、**手机 App（iOS / Android / 跨端 / 小程序）** 还是 **B端后台管理系统**。
2. 若使用场景或审美偏好尚不清晰，最多用 **2~3 个生活化问题**（附推荐默认项）引导用户：谁在什么场景下用、核心要办成哪件事、想要什么第一眼感觉（或觉得哪 1~2 个现有产品好看 / 最讨厌什么样子）。**严禁追问 CSS 参数或设计流派行话**。
3. 将用户的感性描述翻译为具体的色温、明暗、圆角、信息密度与排版策略，用一句通俗中文复述对焦。

### 第 2 步：看样选感觉（用可视化小样激发内心想法）

方向尚未锁定时，**用看得见的画面代替抽象文字确认**：

1. 按 [capability-routing.md](references/capability-routing.md) 先调用 `ui-ux-pro-max` 定向检索匹配产品类型的色板、字体搭配与组件参考，并结合 `impeccable` 对应模式规则（展示型 `Persuade` / 后台工具型 `Operate` / 原生移动端规范）。
2. **产出 2~3 套拉开实质差距的首屏可视化小样**（同时改变布局结构与色温/质感，而非只换主色）：
   - **Web / 后台**：生成可直接在浏览器或宿主预览打开的单文件自包含 HTML 交互样稿（填入真实中文业务文案与合理数据）；
   - **手机 App**：按真实手机竖屏视口（`390×844`）制作并排或可切换的可交互样稿（或配合宿主图像能力生成高保真界面效果图）。
3. 简短说明每套方案的气质与取舍，主动引导用户**混搭与微调**（例如：“要 A 的配色 + B 的紧凑表格，再温和一点”）。根据反馈快速迭代小样，直至用户拍板“就是这个感觉”（若用户已明确授权全权自主设计，则选最优方案说明依据后继续）。

### 第 3 步：高审美底线实现与真机/视口自检

编码实现时读取 [craft-principles.md](references/craft-principles.md) 及目标端对应的 [platform-checks.md](references/platform-checks.md) 章节，强制执行**反 AI 廉价感底线**：

- **禁套路装饰**：严禁标题使用蓝紫渐变字、严禁无意义的霓虹发光与滥用毛玻璃、严禁拿 Emoji（📊🔥✨）冒充产品图标（统一使用精致线性/面性 SVG 图标库或平台原生图标）。
- **克制层级与留白**：禁止“卡片套卡片再加粗边框”的套娃结构，禁止全屏堆满等高三列小卡片；同一容器只选一种深度表达（细边框、微底色差或单层柔和偏移阴影），组外留白大于组内间距。
- **清晰色彩与数字排版**：正文对比度 ≥ 4.5:1；彩底或暖底上的次要文字带同色相微调而非死灰；后台表格、金额与统计指标强制开启等宽数字（`tabular-nums`）并对齐。
- **三端原生体感**：
  - *手机 App*：遵守 iOS HIG / Android Material 3 规范，处理好刘海/灵动岛/底部手势条安全区，触控热区 ≥ 44pt/48dp，严禁照搬桌面顶栏或依赖鼠标 hover；
  - *后台管理*：导航固定清晰，筛选器与表格紧凑顺手，优先抽屉/行内操作减少弹窗打断；
  - *Web App*：兼顾桌面宽屏最大阅读列宽与手机窄屏重排，不出现意外横向滚动条。
- **真实数据与完整状态**：使用贴合业务的真实中文文案与合理边界数据（禁填 `Lorem ipsum` 或 `测试123`），补齐 `加载中 / 空状态引导 / 表单就近报错 / 禁用与点击反馈`。
- **实看渲染验证**：具备运行或预览条件时，必须在目标桌面与移动视口实际打开查看排版与折行表现（Web 项目可配合 `impeccable detect` 扫描静态坏味道），修完视觉瑕疵再交付；无法运行时如实说明未实测的视口范围。

### 第 4 步：固化设计系统（保证后续页面同样漂亮）

首屏或核心流程获确认并落地后，将已验证的色板角色（背景、表面、主色、状态色）、字体与字阶、圆角与间距节奏、导航壳子及核心组件约定沉淀到项目的 `DESIGN.md`（无既有位置时参考 [DESIGN.template.md](assets/DESIGN.template.md) 裁剪）及代码样式变量中。后续开发或由 `$x-dev` / `$x-spec` 推进其余页面时直接复用，确保整套应用从第 1 页到第 N 页保持统一的高水准审美。
