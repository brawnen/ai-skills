# 产品界面设计

面向 **Web App**、**手机 App** 与 **后台管理系统** 的全局高审美 UI/UX 设计主控入口。核心使命是：听懂非专业术语的直白描述与对标偏好，通过“一页式看样选感觉”不断引导出用户真正想要的界面，用精致度工程微操消灭 AI 廉价塑料感，并在定调后通过三视口实景走查与设计系统固化水准。

## 场景分流（按任务成熟度自动选路）

- **0→1 新产品 / 新核心模块 / 整体改版（视觉方向未定）**：完整执行下方 **「四步渐进引导流」**（先对焦与看样定调，未确认方向前绝不盲写大批业务代码）。
- **已有成型设计系统 / 既有风格内新增常规页面**：直接读取并继承项目现有 `DESIGN.md`（及其 `Agent Prompt Guide` 速查卡）、样式 Tokens 与导航壳子，不为单个子页面重搞一套新风格；仅当本页布局存在明显取舍时给 2 个轻量结构方案确认后落地。
- **既有界面不好看 / 体验打磨 / 实景走查挑刺**：读取 [review-rubric.md](references/review-rubric.md) 或按 [capability-routing.md](references/capability-routing.md) 调用 `impeccable` 的 `critique` / `polish` / `bolder` / `quieter` / `harden`，并在可预览环境下用宿主内置浏览器做三视口实景走查与前后对照修复。
- **单处明确的样式小修（如改个间距或对齐）**：直接交回宿主修改并验证，不走完整流程。

## 0→1 与改版：四步渐进引导流

### 第 1 步：大白话对焦与标杆基因匹配（禁专业术语）

读取 [discovery-and-prototyping.md](references/discovery-and-prototyping.md)，用户提到具体参考产品或风格倾向时一并读取 [brand-archetypes.md](references/brand-archetypes.md)。先复用已有需求或 `x-req` 产物，能查证的业务事实绝不重复提问。

1. 自动判定目标形态：**C端/品牌 Web App**、**手机 App（iOS / Android / 跨端 / 小程序）** 还是 **B端后台管理系统**。
2. 若使用场景或审美偏好尚不清晰，最多用 **2~3 个生活化问题**（附推荐默认项）引导用户：谁在什么场景下用、核心要办成哪件事、想要什么第一眼感觉（或觉得哪 1~2 个现有产品顺眼 / 最讨厌什么样子）。**严禁追问 CSS 参数或设计流派行话**。
3. 结合感性词翻译表与标杆产品设计基因卡（如 Linear 工作台、Stripe 高信任商务、Apple/Airbnb 原生温润移动、Claude 人文阅读、Vercel 极简科技），将口语描述转化为精确的色温比例、边框/阴影公式、圆角梯度与排版密度，用一句通俗中文向用户复述对焦。

### 第 2 步：一页式看样选感觉（用对比看板激发内心想法）

方向尚未锁定时，**用看得见的整合对比看板代替零散文件或抽象文字确认**：

1. 按 [capability-routing.md](references/capability-routing.md) 先调用 `ui-ux-pro-max` 定向检索匹配产品类型的色板、字体搭配与技术栈实践，并结合 `impeccable` 对应模式规则（展示型 `Persuade` / 后台工具型 `Operate` / 原生移动端规范）。
2. **产出单页可切换/并排对比的首屏选样看板（Comparison Board）**：
   - 内含 **2~3 套在布局结构与视觉气质上真正拉开差距的首屏方案**（填入真实中文业务文案与模拟数据）；
   - 看板顶栏支持一键切换查看单套方案、同屏并排对比，以及桌面宽屏 / 手机竖屏（`390×844`）视口切换（需强视觉概念时也可配合宿主生图工具）。
3. 每套只用 2 句大白话点出特点，主动引导用户**混搭与拧旋钮微调**（如“要 A 的清爽配色 + B 的紧凑表格，再温和一点”）。根据反馈快速刷新看板，直至用户拍板“就是这个感觉”（若用户已明确授权全权自主设计，则选最优方案说明依据后继续）。

### 第 3 步：高审美微操实现与三视口实景走查

编码实现时读取 [craft-principles.md](references/craft-principles.md) 及目标端对应的 [platform-checks.md](references/platform-checks.md) 章节，严格执行**反 AI 塑料感与精致度微操铁律**：

- **禁套路装饰与单屏单主色**：严禁蓝紫渐变字、无意义霓虹光晕与 Emoji 冒充图标（统一用精致 SVG 图标库或原生图标）；**同一任务视图最多只放 1 个实心品牌主色按钮**，其余一律降为次级按钮，禁止卡片套卡片。
- **几何与排版精度**：嵌套圆角遵循同心公式 `外圆角 = 内圆角 + 内边距`；大标题启用 `text-wrap: balance` 防单字掉行；正文对比度 ≥ 4.5:1；表格、金额与统计指标强制等宽数字（`tabular-nums`）；微动效仅改 `transform / opacity`（`150–200ms ease-out`），异步加载优先骨架屏。
- **三端人体工学与原生规范**：
  - *手机 App*：严格遵守**竖屏三分法拇指热区**（主操作与导航沉入底部 1/3 自然触达区，严禁把高频提交塞在右上角小字），弹层优先采用 **Bottom Sheet（底部半屏抽屉）**，处理好安全区与软键盘遮挡，移动端 Web 全屏高度统一用 `100dvh`；
  - *后台管理*：遵守 `8pt` 间距栅格与标准紧凑拓扑（页头与唯一主动作 → 单行高频筛选 → 勾选批量条 → 右对齐数字表格与抽屉编辑）；
  - *Web App*：控制宽屏最大阅读宽度，保证窄屏自适应重排无横向溢出，复杂浮层复用统一无障碍原语，纯图标按钮必配 `aria-label`。
- **三视口内置浏览器实景走查（`375px / 768px / 1440px`）**：使用贴合业务的真实中文文案，补齐 `加载骨架 / 空状态引导 / 表单就近报错 / 禁用反馈`。具备运行或预览条件时，调用宿主内置隔离浏览器在目标视口（Web/响应式核对 `375px` 手机、`768px` 平板、`1440px` 桌面；纯移动或纯桌面聚焦对应端）**真实点击走通核心交互、抽屉/弹窗与异常状态**，同步检查 Console 报错、接口异常、横向溢出、吸底栏遮挡与视觉走样（Web 可配合 `impeccable detect` 扫描静态坏味道），修复后复看确认干净再交付。

### 第 4 步：固化设计体系与编码速查卡

首屏或核心流程获确认并落地后，按 [DESIGN.template.md](assets/DESIGN.template.md) 裁剪更新项目的 `DESIGN.md`（务必填实第 12 节 **`Agent Prompt Guide` 编码速查卡**）及代码样式变量；0→1 新项目在需要时可保留一份轻量单文件色板与核心组件预览页，方便直观验收。后续由 `$x-dev` / `$x-spec` 推进其余页面时直接读取速查卡与样式变量，确保整套应用从第 1 页到第 N 页保持同样漂亮、统一的水准。
