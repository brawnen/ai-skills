# 大白话审美翻译与看样引导协议

专为“非专业设计师背景、但对界面美观度与产品质感要求高”的开发场景制定。贯穿 **Web App**、**手机 App** 与 **后台管理系统** 的 0→1 设计或改版全过程。

## 1. 严禁设计黑话：提问与沟通准则

- **禁止询问专业术语或参数**：绝不问用户“想要 Bento Grid、Neobrutalism 还是毛玻璃？”“字阶比例用 1.25 还是 1.333？”“圆角要几 px？”。
- **每轮最多 2~3 个直白生活化问题**（能从代码或需求推断的绝不反问，且尽量附带推荐选项）：
  1. **场景与核心动作**：谁在什么情境下用它（例如：通勤路上单手刷手机、安静书房阅读、还是双屏高强度处理工单），打开第一眼最核心要完成哪一件事？
  2. **气质参考（听感觉、找对标）**：希望它给人什么第一感觉（如：清爽干练、温暖治愈、专业稳重、年轻有活力），或者平时有没有 1~2 个你觉得“长得很顺眼”的 App / 网站？
  3. **排雷边界**：有没有你最反感的样子（如：讨厌黑底刺眼荧光色、讨厌像老式 ERP 一样密密麻麻、讨厌花哨动画挡住正事）？

## 2. 感性大白话 → 专业设计系统翻译表

收到用户的日常描述后，在内部将其转化为精确的设计参数，并用直白语言向用户一句话复述确认：

| 用户的日常表达 | 自动映射的专业设计决策（色板 / 排版 / 空间 / 形体） |
| :--- | :--- |
| **“清爽、干净、现代感、别太乱”** | 微冷白/浅石板灰画布（`#F8FAFC`）+ 纯白工作区；单一高辨识度主色（仅用于主按钮与激活态，占比 <10%）；大组间距（`24–32px`）替代多余实线框；`8–10px` 适度圆角；无装饰渐变。 |
| **“大气、高级感、有质感、不廉价”** | 克制色相（深墨黑/深海蓝或暖炭灰配单一金属/宝石强调色）；强字重与字号对比（大标题紧凑字距 `-0.025em`，正文舒展行高 `1.65`）；大量呼吸留白；单层细腻微偏移柔影或 `1px` 低对比细边（绝不同时叠粗边与重阴影）。 |
| **“温暖、亲切、生活化、别太死板”** | 暖米白/燕麦色底（`#FAF8F5`）配带暖调的深棕灰文字（禁用冷死灰）；珊瑚橙/森林绿/琥珀黄等自然主色；较大亲和圆角（`14–18px`）；柔和色块分组与轻快微弹反馈。 |
| **“像现代 SaaS / 别像上世纪老后台”** | 侧边窄导航或紧凑双层壳（参考 Linear / Stripe / 飞书质感）；筛选项与表头一体化收拢，去掉笨重的多重外框与斑马纹；表格数字强制等宽对齐（`tabular-nums`）；状态用柔和底色胶囊徽章（绿/琥珀/红带圆点与文字）；编辑用右侧抽屉替代满屏乱跳弹窗。 |
| **“专业稳重、值得信赖（金融/医疗/政企）”** | 高可读对比度（≥7:1 核心数据）；海军蓝/深青/墨绿等高信任度主色；结构对称规整、数据单位与口径醒目；交互反馈确定克制，零花哨动效。 |
| **“大众易用、操作直觉（含中老年/下沉场景）”** | 字号整体上调一档（正文 ≥16–17px），高对比清晰边界；单屏只突出 1 个核心大按钮（触控高 ≥48–52px）；图标全部配直白中文标签（绝不用纯图标猜含义），步骤拆短。 |

## 3. 三类产品形态的设计重心（自动匹配）

| 产品形态 | 美感来源（怎样才算漂亮） | 必须遵守的结构铁律 |
| :--- | :--- | :--- |
| **Web App（C端 / 官网 / 独立产品）** | **首屏张力与独特气质**：第一屏直接展示核心产品机制或代表画面，有记忆点与滚动节奏变化。 | 拒绝“大字标题 + 两个按钮 + 底下三张一模一样图标小卡片”的平庸 AI 模板；宽屏有最大阅读宽度控制，窄屏自适应重排。 |
| **手机 App（iOS / Android / RN / Flutter / 小程序）** | **原生顺滑手感与卡片呼吸感**：贴合真实竖屏比例，拇指单手好点，字体层级干净，安全区留白自然。 | **严禁把桌面网页顶栏、多列小字表格或鼠标 hover 交互搬进手机**；底部导航 ≤5 项，触控热区 ≥44pt/48dp，避开刘海/灵动岛与底部手势条。 |
| **后台管理系统（Admin / SaaS 工作台）** | **秩序感、对齐精度与克制配色**：一眼扫清关键指标、异常状态与高频操作，久看不累。 | 走 `Operate` 模式——业务效率高于艺术表达：导航固定可预测，筛选/搜索/批量操作就近收敛，表格列右对齐数字与固定操作列，必配空数据与筛选无结果态。 |

## 4. “看样选感觉”渐进式引导流（核心机制）

非设计背景用户很难凭文字脑补画面。在 0→1 新产品或改版未锁定风格时，**用看得见的小样代替抽象讨论**：

1. **一次给 2~3 套真正拉开差距的首屏小样**：
   - 每套小样必须在**至少两个维度**上明显不同（例如：**布局结构**［左导航工作台 vs 顶部聚焦单列 vs 分栏看板］ + **视觉色温/密度**［极简留白冷调 vs 温暖亲和色块 vs 紧凑高密专业风］），只换一个按钮颜色不算多方案。
   - **呈现载体**：
     - Web / 后台：优先生成可在浏览器或宿主预览面板直接打开查看的自包含 HTML 首屏交互样稿（带真实中文业务文案与模拟数据）；
     - 手机 App：在自包含 HTML 预览中按真实手机竖屏外框（`390×844`）并排或可切换展示 2~3 套首屏样稿（或配合宿主生图工具输出高保真设备界面图）。
2. **用“拼装 + 旋钮”话术引导用户表达内心想法**：
   - 展示小样时，每套只用 **2 句话**点出特点（“这套胜在……，适合……”），然后直接引导：
     > “你第一眼更顺眼哪一套？完全可以混搭（比如**要 A 的配色 + B 的布局**），也可以直接用大白话调方向：**更清爽留白一点 / 信息再紧凑一点 / 换个更暖的颜色 / 更大胆一点**。”
3. **小步收敛再进正式工程**：
   - 若用户提出混搭或调整，快速刷新选中的那套小样确认“对味”后，再开始写正式多页面业务组件代码，避免写完几千行代码才发现整体审美不对路。
