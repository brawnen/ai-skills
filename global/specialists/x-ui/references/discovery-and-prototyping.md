# 大白话审美翻译与看样引导协议

专为“非专业设计师背景、但对界面美观度与产品质感要求高”的开发场景制定。融合 [`garrytan/gstack`](https://github.com/garrytan/gstack)（`design-shotgun` 单页对比看板与审美偏好记忆）及 [`VoltAgent/awesome-design-md`](https://github.com/VoltAgent/awesome-design-md) 对标思路，贯穿 **Web App**、**手机 App** 与 **后台管理系统** 的 0→1 设计或改版全过程。

## 1. 严禁设计黑话：提问与沟通准则

- **禁止询问专业术语或参数**：绝不问用户“想要 Bento Grid、Neobrutalism 还是毛玻璃？”“字阶比例用 1.25 还是 1.333？”“圆角要几 px？”。
- **每轮最多 2~3 个直白生活化问题**（能从代码或需求推断的绝不反问，且尽量附带推荐默认项）：
  1. **场景与核心动作**：谁在什么情境下用它（如：通勤路上单手刷手机、安静书房阅读、还是办公室双屏高强度处理业务），打开第一眼最核心要办成哪件事？
  2. **气质与顺眼参考**：希望它给人什么第一感觉（如：清爽干练、温暖治愈、专业稳重），或者平时有没有 1~2 个你觉得“长得很顺眼”的 App / 网站（可直接关联 [brand-archetypes.md](brand-archetypes.md) 中的标杆基因卡）？
  3. **排雷边界**：有没有你最反感的样子（如：讨厌黑底刺眼荧光色、讨厌像老式 ERP 一样密密麻麻、讨厌花哨动画挡住正事）？

## 2. 感性大白话 → 专业设计系统翻译表

收到用户的日常描述后，在内部结合 [brand-archetypes.md](brand-archetypes.md) 将其转化为精确的设计参数，并用直白语言向用户一句话复述确认：

| 用户的日常表达 | 自动映射的专业设计决策（色板 / 排版 / 空间 / 对标基因） |
| :--- | :--- |
| **“清爽、干净、现代感、别太乱”** | 对齐 **Linear / 飞书基因**：微冷白画布（`#F8FAFC`）+ 纯白工作区；单一主色占比 `<5%`；`1px` 低对比细边与 `24–32px` 留白分组替代笨重外框；`6–10px` 利落圆角。 |
| **“大气、高级感、有质感、不廉价”** | 对齐 **Stripe / Vercel 基因**：深海蓝或暖炭黑文字（禁用刺眼纯色块堆砌）；强字重字号对比（大标题字距 `-0.025em` + `text-wrap: balance`）；充裕呼吸留白；单层细腻柔影。 |
| **“温暖、亲切、生活化、别太死板”** | 对齐 **Airbnb / Claude 基因**：暖米白/燕麦底（`#FAF9F5`）配暖棕灰文字（禁用冷死灰）；珊瑚橙/鼠尾草绿等自然主色；`14–18px` 亲和圆角与去外框图文卡片。 |
| **“像现代 SaaS / 别像上世纪老后台”** | 紧凑侧边栏工作台；筛选项与表头一体化收拢，单屏仅保留 **1 个实心主色按钮**；表格数字强制等宽对齐（`tabular-nums`）；右侧抽屉编辑替代满屏弹窗。 |
| **“像原生大厂手机 App、单手好点”** | 对齐 **Apple HIG / Material 3 基因**：严格遵守手机竖屏三分法拇指热区（主操作与导航沉底，右上角不塞高频小字）；分层灰白底色，弹出操作优先用底部半屏抽屉（Bottom Sheet）。 |
| **“大众易用、操作直觉（含长辈/下沉场景）”** | 字号整体上调一档（正文 ≥16–17px），高对比清晰边界；单屏只突出 1 个大触控主按钮（高度 ≥48–52px）；所有图标必配直白中文标签，步骤拆短。 |

## 3. “一页式对比选样看板”渐进引导流（核心机制）

非设计背景用户很难凭文字脑补画面，也怕在多个零散文件间来回切换比较。在 0→1 新产品或改版未锁定风格时，**用一个整合选样看板激发用户的真实想法**：

1. **生成单页可切换/并排对比的 HTML 选样看板（Comparison Board）**：
   - 包含 **2~3 套拉开实质差距的首屏方案**——每套必须在**布局结构**（如左导航工作台 vs 顶部聚焦流 vs 分栏看板）和**视觉气质/密度**（如清爽冷白极简 vs 温润亲和色块 vs 高密专业数据风）两个轴上明显不同，只换按钮颜色不算多方案。
   - **看板交互结构**（纯内联 HTML/CSS + 几行零依赖切换脚本）：
     - 顶部固定一条轻量极简选样控制栏：支持一键切换查看 `[方案 A]`、`[方案 B]`、`[方案 C]` 或 `[并排同屏对比]`；
     - 针对 Web App 支持一键切换 `[桌面宽屏 / 手机窄屏]` 预览；针对手机 App 直接以真实竖屏手机视口框（`390×844`）并排呈现 2~3 台手机首屏效果（需要概念视觉冲击时也可配合宿主生图工具）。
     - 样稿内部必须填入贴近真实业务的中文名称、数据和关键状态，禁用 `Lorem ipsum` 假文。
2. **用“拼装 + 旋钮”话术引导用户表达内心想法**：
   - 每套方案只用 **2 句大白话**点明特点与取舍，随后直接引导：
     > “打开看板对比一下，第一眼哪套最顺眼？完全可以混搭（比如**要 A 的清爽配色 + B 的紧凑布局**），也可以直接拧旋钮：**再留白透气一点 / 信息再紧凑一点 / 颜色再暖一点 / 更大胆一点**。”
3. **小步收敛与可选审美记忆（Taste Memory）**：
   - 根据用户反馈快速刷新看板，直到用户拍板“就是这个味儿”后再展开正式多页面组件编码。
   - 若用户在项目定调时明确表达了跨项目通用的长期审美偏好（如“我以后所有后台都喜欢这种浅色高密飞书风”），仅在用户希望记住时简要沉淀到项目或个人偏好说明中，作为下次新项目的 1 号默认候选起点（仍保留差异化备选供对比）。
