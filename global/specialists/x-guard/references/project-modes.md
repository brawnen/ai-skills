# 三类项目适配与底座矩阵

接手项目建立或补齐静态检查底座时，先判定项目类型，再按对应安全策略选型与接线。

## 1. 三类项目安全策略

| 项目类型 | 识别信号 | 自动构建策略 | 必须遵守的保护机制 |
| --- | --- | --- | --- |
| **0→1 空白项目** | 刚初始化、无历史包袱、尚无业务分层 | 接入语言最轻现代基础检查（格式 + 类型 + 基础静态分析）+ 预留自定义规则目录（如 `rules/ast-grep`）+ 统一入口 `scripts/check`（或复用既有入口） | 技术栈未定时暂缓选择工具，只铺极简底座，不预塞几十条过度规则拖慢早期原型探索 |
| **接手他人存量项目** | 已有业务代码、历史提交与既有工具链 | 先跑通并复用现有 linter/CI；结合近期 commits、reverts、review 评论与 workaround 注释中的高频失误（≥2 次），连同目录分层、公共组件/请求封装、安全红线和文档明文规则提炼首批高确定性规则（建议 2~5 条起步） | 仅对确有历史违规的规则建立逐处豁免（写明原因、过期日期与人工批准），验证同文件新增违规仍失败，绝不让老代码瞬间报大量红错 |
| **开源项目** | 面向外部上游仓提 PR，含 `CONTRIBUTING.md`、上游 CI 或开源许可 | **严格尊重上游**：先读 `CONTRIBUTING.md`、上游 CI 和 linter 配置，优先跑通上游检查 | **不污染 git / PR**：个人额外约束放本地忽略路径（如 `.git/info/exclude` 或未跟踪本地脚本），绝不把个人规则、依赖或配置混进上游提交 |

## 2. 跨语言底座与引擎选型

不要自研跨语言解析器；把职责拆给最合适的现成工具，全部收口到项目唯一检查入口：

| 检查层 | 负责内容 | 常见语言推荐底座（优先沿用项目已有工具） |
| --- | --- | --- |
| **语言原生基础检查** | 格式、强类型检查、常见语言级 bug | Go: `gofmt` + `go vet` / `golangci-lint`<br>TS/JS: `oxlint` / `eslint` + `tsc --noEmit`<br>Python: `ruff` + `pyright`/`mypy`<br>Rust: `rustfmt --check` + `clippy`<br>Kotlin/Android: `ktlint` / `detekt` |
| **跨语言自定义 AST 规则** | 禁用特定 API/裸控件、特定调用模式、禁止不安全参数等单文件 AST 规则 | 优先 `ast-grep`（单二进制，一套 YAML 规则 + 内置测试覆盖 20+ 语言） |
| **强类型 / 跨文件架构检查** | 跨层 import 边界、深模块根入口隐藏、目录布局、生成物一致性、配置红线 | 语言原生测试或轻量校验脚本（如 Go `go/ast` 架构测试、TS `dependency-cruiser` 见同目录 [ts-deep-modules.md](ts-deep-modules.md)、Python 轻量结构脚本） |

选型原则：
- 若仓库已有成熟的语言原生 linter 插件体系（如已有 ESLint flat config 或 Go `*_test.go` 架构测试），优先就近复用，不为了统一而强行引入多余二进制。
- 多语言仓库（如 Go + Vue + Python + 静态站）需要一致的自定义模式规则时，优先引入 `ast-grep` 作为统一自定义规则层。

## 3. 统一触发闭环

- **唯一检查入口**：无论什么语言栈，尽量统一收口到一个可记忆入口（沿用项目已有的 `scripts/verify.sh` / `Makefile` / `justfile` / `package.json`；空白项目默认 `scripts/check`），确保人、Agent、CI 调用完全一致的检查集合。
- **可选本地 Git Hook**：跨语言项目需要 `pre-commit` / `pre-push` 拦截时，优先推荐单二进制、语言无关的 `lefthook`（而非绑死 Node.js 的工具）；仅在项目适合且经确认时引入，不静默安装全局二进制或覆盖已有 hooks。

## 4. 实施前确认清单

在向用户提议落地 `init / audit` 方案时，固定给出以下 4 项精简信息：

1. **项目类型与现状**：已发现的语言栈、现有检查入口与 CI 门禁。
2. **拟增项**：基础工具补齐或首批高确定性规则清单（每条写明来源依据，不编造隐性业务规则）。
3. **误报风险与存量豁免**：是否需要 Baseline / 增量模式，或开源项目的本地隔离路径。
4. **统一入口接线点**：新增检查挂到哪个命令，以及需要的前置工具（若本机缺失则标明）。
