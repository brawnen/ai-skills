# 研发交付

选择用户要求的范围：仅讨论/方案时止于相应产物；已授权完整开发时复用已有决定与授权推进，不让用户逐阶段重复输入命令。小且明确的改动交回宿主直接实施与相关检查。

请求带有任务编号、链接或任务文件时，开工或恢复前先[核对任务归属与标题](references/tickets.md#核对任务归属与标题)，在首条实质进展中报出仓库、编号和原始标题。指向唯一且符合请求时直接继续。

按实际缺口读取阶段协议：

- 需求不清：[需求澄清](references/requirements.md)；业务术语/状态冲突时选择可用的 model。
- 需技术与验收契约：[规格](references/spec.md)；无需独立交接且相关设计已就绪时可附简短实施顺序直接实施。
- 初版规格形成或恢复任务时，按 [界面设计就绪检查](references/spec.md#界面设计就绪检查) 衔接必要的页面/交互设计：有缺口主动说明并在授权内形成可查看方案，交互不确定时才做原型；决定回写规格后再拆解或实施相关界面。已有设计或无需界面的任务直接继续。
- 跨人/会话领取、依赖管理或并行：[任务](references/tickets.md)；不按切片数或 token 阈值拆任务。
- 进入代码：[实施](references/implementation.md)；并行模式只在明确授权且宿主可用时读取 [并行集成](references/parallel-implementation.md)。
- 需要运行验收时读取本入口 [验证方法](references/verification.md) 并复用项目 verify-app/可靠脚本；入口缺失时使用可用的 setup-verification，普通快速测试由宿主执行。
- 审查与交接：[双轴审查](references/review.md)、[PR](references/pr.md)、[产物/发布契约](references/artifacts.md)；重要构建结束后按需读取 [复盘](references/retro.md)。

这些是本入口在用户授权范围内按需读取的协议，不是假定能调用另一个显式入口。只加载当前阶段；不自动启用 TDD、多代理、完整 UI 或全量测试。跨边界风险、真实数据库操作、疑难故障分别选择相关参考、review-db 和 debug。

代码合并遵循用户授权、项目分支策略和门禁；测试环境部署沿用既有权限。核对实际制品与 smoke，未运行项明确标注。生产部署、回滚和生产写入由人执行，agent 准备发布包并做允许的只读观察。

连贯上下文有效时继续；交接、隔离任务或上下文质量下降时携带工件指针、必要原始证据、版本、决定与缺口。环境/权限阻塞仅停止依赖部分；故障影响扩大时先保存观测并在允许范围内控制影响。
