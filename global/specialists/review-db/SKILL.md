# 数据库变更安全

## 决策入口

从现有配置、migration 和用户上下文确认目标环境、数据库及版本、操作对象和授权范围；不能查证且会影响安全执行的信息才询问。编写和验证脚本不等于授权执行生产写入，已有明确授权应复用。

按实际后果选择检查强度：本地临时实验可只确认行为和恢复方式；staging 验证实际可运行性及与生产的差异；生产执行需要影响边界、失败检测、停止条件和可执行恢复路径的证据。环境名称本身不能替代数据重要性和操作风险判断。

## 风险模型

| 操作 | 需要回答的问题 |
| --- | --- |
| 表结构与约束 | 锁与重写代价是什么？旧新代码是否共存？默认值、NULL、约束验证和 DDL 事务语义是否影响兼容？ |
| 索引 | 当前数据库版本支持什么创建方式？磁盘、写入负担、锁等待和失败后残留如何处理？关键查询是否改善或退化？ |
| 查询变更 | 实际计划、数据分布和负载是否支持预期收益？扫描、排序、锁与缓存影响是否在预算内？ |
| 回填与迁移 | 如何分批、限速、记录进度和安全重跑？业务并发写入、重复处理和中途失败会否导致覆盖或漏处理？ |
| 数据修复与删除 | 目标集合是否准确且有边界？修改前值如何保留？执行时如何防止范围漂移、误更新或误删除？ |

只展开实际相关的数据库方言和风险，不要求列出其它数据库的差异。

## 执行前证据

按操作选择适用检查，说明关键缺口；这些是取证手段，不是每次必须执行的命令清单。

- **范围与规模**：用过滤条件、代表样本、统计信息或有成本边界的计数核对目标集合。精确数量影响执行决策时再选择安全的计数方式，不默认对大表做全量 `COUNT(*)`。
- **计划与资源**：对适用查询检查执行计划、锁等待、事务时长和磁盘需求。计划不等于实测；带实际执行语义的分析命令按真实副作用处理。全表扫描是否可接受取决于目标数据比例和资源预算，不以「必须走索引」替代判断。
- **兼容与演练**：在适合的隔离环境验证脚本、旧新版本兼容及失败恢复；说明规模、负载或版本差异。无法等比例演练时给出替代证据和未验证风险，不宣称已证明生产安全。
- **并发与重跑**：验证幂等键、检查点、游标或条件更新如何处理业务同时写入及中断恢复。不要只因使用分批就宣称幂等。
- **停止与恢复**：给出可观察的停止阈值、执行负责人或操作者，以及中断后的事务和数据状态。终止会话可能触发漫长回滚，不能把 KILL 视作立即恢复的通用方案。

## 恢复策略

根据实际变更选择事务回滚、保存修改前值并逆向恢复、备份恢复、向前修复或兼容窗口内回退代码；不强制所有操作提供逆向 SQL。

- 明确恢复所需的数据、权限、时间、可接受数据损失及验证方式。
- 回填后发生的新业务写入不能被恢复脚本无条件覆盖。
- 不可逆操作如实标明；缺少与后果相称的恢复或兜底证据时，继续完成脚本和隔离验证，阻止的是不具备条件的实际执行。
- schema 变更和数据回填分别描述，明确顺序和旧新代码共存窗口。

## 输出与边界

先给出当前可推进的动作及阻塞项，再提供实际命中的风险、影响范围、恢复路径和验证证据。按任务规模组织内容，不强制空章节或为不适用项填写「无」。

没有 WHERE、条件过宽或依赖应用侧过滤的写入必须核对是否确实需要操作全表；合法的全表变更需有明确范围授权和恢复安排，不根据 SQL 字面形态推断授权或安全性。

语法检查、计划检查、staging 演练和生产结果是不同证据。只报告实际验证层级；外层测试和执行调度由宿主负责。
