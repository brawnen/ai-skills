# 红队实证审查

专门从对抗视角尝试打破目标改动或技术方案。**硬约束：一条发现只有被真实运行证明（失败测试、复现脚本或真实命令输出）且确实打破原意图时才允许保留**；不输出未经运行的猜测、代码风格或命名建议。只报告已验证发现，不自动修改业务代码。

需要详细攻击面、隔离副本规范与复跑验真规则时，读取 [对抗实证协议](references/adversarial-protocol.md)。

## 流程

1. **界定范围与意图**：确定审查目标（用户指定文件/方案/提交，否则为当前分支相对可解析基线的完整 diff，含工作区未提交改动）。用简短直白的话复述目标意图；意图不明且无法从需求/提交确认时先向用户核对。
2. **隔离对抗验证**：在隔离副本或临时 worktree 中（保留当前未提交改动，不污染用户工作区）针对边界输入、权限越界、并发/重入、失败恢复、契约漂移和隐含假设发起定向破坏测试；方案/设计阶段则对真实代码库或最小原型做可运行探针。宿主支持且获并行授权时，可派多个全新上下文对抗子代理并行攻击。
3. **独立复跑验真与去重**：主协调者逐条复跑候选发现的精确命令，仅保留输出明确复现失败且打破原意图的条目，其余全部丢弃；同一根因合并为一条，并在收尾时清理自己创建的临时副本/worktree。
4. **交付结论**：汇报「意图复述」「已验证发现（标题、复现命令、实际输出、与意图预期差异、根因定位）」及「验证范围与未覆盖限制」。**未发现可复现缺陷是完全合法的有效结论**，严禁为凑数输出纸上臆测。
