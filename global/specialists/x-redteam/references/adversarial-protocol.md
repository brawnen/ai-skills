# 对抗实证审查协议

借鉴 `pstack/interrogate`（Lauren Tan，0.15.46）的实证红队思路，本地化为不绑定固定模型或外部编排器的通用对抗审查协议。

## 1. 范围与隔离基线

- **代码改动**：覆盖基线到当前工作树的全部变更（含已暂存与未暂存）；不得用空的 `HEAD...HEAD` 漏掉工作区。
- **方案或规格**：围绕方案依赖的真实代码路径、API 契约或最小可运行原型进行探针验证。
- **工作区保护**：所有复现脚本、临时变异或失败测试必须放在隔离目录或临时 `git worktree` 中执行，绝不覆盖或污染用户工作区；收尾时仅清理本次自建的临时目录与 worktree。

## 2. 攻击面与对抗指令

无论由单代理顺序执行还是多个全新上下文子代理并行执行，对抗者均遵守同一条铁律：

> 目标是设法打破该改动或方案。每条发现必须给出可独立复跑的真实运行证据（失败测试、最小复现脚本或真实命令输出）。不得上报任何未实际运行的内容——包括代码风格、命名、结构偏好，以及依赖“未来某天改动”才会触发的假设风险。零发现是有效结果。

优先检查高后果攻击面（按目标类型挑选，不机械遍历）：
- **边界与畸形输入**：空值、零值、超大值、重复提交、乱序事件、编码/时区/精度边界。
- **权限与隔离逃逸**：跨租户/跨角色访问、绕过前置校验、未认证或降权调用。
- **状态与并发竞态**：重复回调、重试幂等失效、部分写入中断、读改写竞争。
- **依赖与集成错配**：调用方传参假设、配置缺失、下游超时/非 200 响应、旧数据或旧客户端兼容。

## 3. 二次复跑验真与过滤规则

主协调者对每条候选发现执行验真：

1. 在干净隔离基线上直接运行该发现给出的精确命令。
2. 核对两件事：命令输出确实显示失败或错误行为，且该失败真正违背了已确认的原意图（而非环境缺依赖、测试写错或臆造需求）。
3. 未能复现、属于环境阻塞、或未打破原意图的条目**直接剔除**（环境阻塞可在限制说明中单列，不充当产品缺陷）。
4. 将共享同一根因的多条症状合并，保留最短复现路径。

## 4. 输出结构

- **原意图**：1~3 句直白复述。
- **已验证发现**（若无则明确写“在已测范围内未发现可复现缺陷”）：每条包含：
  - 标题与影响面
  - 精确复现命令
  - 关键实际输出（脱敏）
  - 意图要求的预期结果与根因位置（`file:line`）
- **验证限制**：因缺少凭据、外部环境或未执行而无法攻击的范围（标为未验证）。
