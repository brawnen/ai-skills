# 规则编码与四件套协议

将“第二次原则”（同类纠偏再次出现，或准备向文档追加“禁止/必须”条款）转化为低误报、可自修的确定性护栏。

## 1. 约束漏斗（从强到弱，选最强可行层）

准备沉淀一条新约束时，按以下顺序逐层判断，**能用上层结构阻止的，就不退回下层散文**：

1. **API / 架构设计**：能否调整接口、封装入口或目录可见性，让错误状态根本无法构造？
2. **类型系统 / 编译器**：能否用强类型、受限枚举、泛型或编译选项在编译期直接拦截？
3. **自定义 Lint / AST 静态检查**：能否用语言原生 lint 或 `ast-grep` YAML 规则在静态阶段精准识别违规模式？
4. **轻量架构测试 / 校验脚本 / 运行时断言**：跨文件依赖、目录边界、生成物一致性或运行时不变量，用零重依赖的测试或轻量脚本拦截。
5. **文档规范（最后兜底）**：仅当规则依赖主观设计判断、业务权衡或上下文语义、无法机械判定时，才写入 `AGENTS.md` 或开发规范。

## 2. 四件套交付标准

每条通过层 3 或层 4 落地的自定义规则，交付时必须同时包含以下四件套：

### ① 规则本体（精准匹配，拒绝脆弱正则）
- 优先使用 AST 节点匹配（`ast-grep`、`go/ast`、ESLint AST）或模块依赖图分析；仅在纯文本/配置文件且无 AST 解析器时使用边界明确的正则。
- 明确限定生效文件范围（`files` / 目录路径）与排除范围（测试 fixture、生成代码）。

### ② 正反测试样例（证明有效且不误杀）
- **反例（invalid）**：复发问题使用真实旧错误，首次执行明文契约时可用标明来源的构造反例，验证规则**必定拦截**。
- **正例（valid）**：至少包含 1 个正确替代写法及易混淆的合法边界写法，验证规则**不会误报**。
- 必须实际运行测试并确认通过。

### ③ 面向 Agent 的三段式报错
无论使用 `ast-grep`、ESLint、Go 测试还是 Python 脚本，报错信息必须固定包含三段，让 Agent 跑完检查即可一次自修：

```text
[违反了什么] <具体违规模式与所在位置>
[替代写法]   <推荐使用的封装函数、公共组件或正确路径>
[规范依据]   <对应的规格文档、ADR 或架构约定路径>
```

### ④ 文档同步瘦身与规则退场
- 规则接入并实跑验证生效后，检查 `AGENTS.md` 或相关开发手册中对应的重复“禁止/必须”散文条款。
- 若项目在 `AGENTS.md` 中保留规则清单，为每条标注对应的**执行机制**（类型 / lint / 测试 / 仅人工判断）；曾标为“仅文档”的规则若再次违规，本次必须升级到机械层。
- 删除可被 lint 完整替代的冗长禁令（必要时只留简短指针或无法机械化的设计理由）；一旦某类错误已被架构或类型彻底根除，直接将该条**退场删除**，避免文档与规则双头维护。

## 3. 存量豁免（Baseline）与反逃生舱要求

- **不刷红老代码**：在存量项目新增规则时，按规则、相对路径、违规节点及其上下文定位既有命中，记录原因、过期日期与人工批准。可改用可信基线版本的差异定位。逐处匹配，重复命中逐个消耗；仅凭整文件 ignores 或总数未增加无法区分新旧。修复后移除过期豁免，检查时禁止自动刷新基线。用同文件保留旧违规再新增一处、修复旧处改在另一处违规两种变更验收。
- **反绕过与反逃生舱原则**：禁止为通过检查而在新增代码中添加 `eslint-disable`、`@ts-ignore`、`nolint` 或 `IMPORTANT: do not remove` 借口注释来掩盖正确性/安全规则，也不得为迁就某次错误放宽规则条件；确需特例必须在违规行注明原因、过期日期与人工批准。
- **挂入统一入口**：每条新规则必须接入项目的统一检查命令（本地与 CI 跑同一入口并保持快速反馈）；执行该入口确认存量基线通过。

## 4. 验证工具确实扫描目标文件

先在隔离副本里选一个本项目真正受规则约束的源文件，从日常或 CI 使用的检查入口运行。写入违规，让入口因该文件、位置及目标规则失败，换回合法实现再通过。另选相似但允许的写法做对照。零扫描、解析失败和工具启动错误分别报告。

HTML 片段的 ast-grep 测试只验证片段匹配。Vue 单文件组件应使用项目已有的 Vue 模板解析器（例如 Vue 3 的 `vue/compiler-sfc` 或 vue-eslint-parser）。扫描项目实际的 `.vue` 路径，针对模板元素及适用的业务上下文匹配，脚本中的同名字符串、注释和允许使用原生元素的公共组件应放行。使用其他引擎时，先证明其语言映射及嵌入语法覆盖实际文件。

例如总部列表只规定标题操作复用公共按钮，检查可限定到相应列表的标题操作插槽。用真实页面的模板把公共按钮换成原生按钮，再从统一入口运行。需要行为证据的问题（如打开抽屉是否重查列表）复用请求及状态回归测试。

Vue 3 示例：在已声明 Vue 依赖的工作区包内读取模板树，供项目自己的节点匹配函数使用。

```js
import { readFileSync } from 'node:fs'
import { parse } from 'vue/compiler-sfc'

function templateRoot(filename) {
  const { descriptor, errors } = parse(readFileSync(filename, 'utf8'), { filename })
  if (errors.length) throw new Error(`${filename}: ${errors.join(', ')}`)
  if (!descriptor.template) return null // 仅有脚本的组件没有内联模板
  if (descriptor.template.src || (descriptor.template.lang && descriptor.template.lang !== 'html') || !descriptor.template.ast) {
    throw new Error(`${filename}: 当前检查器只覆盖内联 HTML 模板`)
  }
  return descriptor.template.ast
}
```

从目标包枚举实际文件并统计扫描范围。对有模板却无法解析或目标路径零命中的情况报告覆盖缺口，以免误报通过。
